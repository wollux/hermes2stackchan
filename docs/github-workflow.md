# GitHub Workflow

Hermes2StackChan uses GitHub as the project source of truth.

## Rules

- Track planned work as GitHub Issues.
- Use labels for type, area, priority, and status.
- Create a feature branch for each implementation slice.
- Open a pull request before merging into `main`.
- Link pull requests to their issues.
- Keep tests and documentation updated with the code.

## Branch Naming

- `feature/issue-N-short-name`
- `fix/issue-N-short-name`
- `docs/issue-N-short-name`

## Pull Requests

Every pull request should include:

- linked issue
- summary of changes
- test result
- remaining risk or follow-up
